# 测试行为，而非实现

测试是关于代码对其用户做了什么的断言：调用方、最终用户或另一个服务。行为是这些用户通过他们所使用的接口能观察到的东西。这包括返回值、错误、他们能读回的状态，以及对外部系统的影响，例如发出一个请求、写入一行记录或发出一条消息。实现是他们无法观察的东西：私有辅助函数、内部调用顺序、中间数据，以及由哪个内部协作者完成了工作。

用两处想象中的编辑来评判每个测试：

- **破坏行为。** 让代码返回错误的值、跳过一个效应，或把效应做两次。如果测试仍然通过，它什么也没证明。常见原因是：断言比契约更宽松、期望值由被测代码计算得出、重述一个常量或提示词字符串而从不运行读取它的代码，以及断言测试自己构造的数据。
- **改动内部。** 保持所有可观察结果不变，重构底下的代码。如果测试现在失败，它就钉在了实现上。它会在每次重构时都需要重写，却仍抓不到任何 bug。

保留能抓住第一处编辑、且在第二处编辑后仍存活的测试。其余的重写或删除。要写出两者兼备的测试，通过用户使用的接口以具体输入驱动代码。从需求推导期望值，而不是从一次代码运行中。断言契约所承诺的，不多也不少。

契约决定，而不是断言的形态。当“空购物车永不收费”是承诺时，断言支付客户端没有被调用就是行为。把它与确实发生收费的用例配对，这样测试才能表明它能看见调用。被 mock 的外部服务收到的载荷是行为，因为该服务会观察到它。对内部辅助函数的调用是实现，因为没有用户能看到它。当没有记录匹配时，空列表就是确切答案；而当测试只需要某个结果时，它就是空洞的检查。精确的错误消息钉住了没有调用方读取的措辞。调用方据以分支的错误类型才是契约。

测试可以钉住不变量而不是调用，例如必须在两张表中都存在的键，或编译期类型检查。不变量就是行为。

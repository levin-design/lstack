# 纠正

操作者一直在为同样的错误反复纠正此仓库中的 agent。改变仓库，让下一个 agent 无法再犯这些错误。

假设每位贡献者都是 agent：它只看到自己打开的文件，复制最近的示例，走能编译的最短路径。这样设计仓库：让从单个文件看正确的改动，对整个仓库也正确。

## 找出错误类别

首先，阅读最近的提交、回滚、评审意见、agent 指令文件，以及解释变通方法的注释。把错误归入类别。同一类错误发生过两次才算成立。

## 在可行的最高层级修复每个类别

1. **用架构消除它。** 让每份状态只有一个所有者，每项任务只有一种受支持的做法。隐藏内部细节，使错误的 import 直接失败。用单一事实来源替换手工同步的列表。删除旧做法和 agent 会复制的死代码。
2. **用类型强制约束，让坏状态无法被写出。** 如果坏代码仍能编译，就加一条 lint 或 CI 检查，让报错信息指出应改用哪个文件、类型或函数。如果该模式已经很普遍，只在改动新增更多时失败。
3. **测试行为。** 修复或删除这样的测试：它检查的行为已损坏却仍然通过，或只有内部实现变化时它就失败。
4. **最后才写文档或 agent 规则，且只针对需要判断的情形。** agent 跳过它们时不会有任何失败。

## 修复并证明

然后立即修复最常见的类别，每类一个提交。证明每个新检查都会在真实的历史错误上失败。在本地和 CI 中运行同一条命令。例外写在违规行上，并附上原因、到期日期和人类批准。

## 维护规则表

最后，在 agent 指令文件中维护一张表，把每条规则与执行它的机制配对。当操作者纠正你时，修复错误并添加规则。如果规则本来就在，却没有任何机制执行它，那就是重复发生，应在同一次改动中按最高层级修复。当某条规则对应的错误已不可能发生，就删掉这条规则。

**回复：** 每个类别的证据、你选择的层级，以及为什么更高层级不可行。

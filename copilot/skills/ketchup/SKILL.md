# Ketchup

向用户交代自他们在 `/ketchup` 之前写下最后一条消息以来，这个对话里发生了什么变化，并帮助他们理解每一处变化，而不只是变化停在哪里。然后列出每一项在等他们做的决定，使他们仅凭你的回复就能做出。通知和子代理结果不是他们的消息。假设用户只记得他们的最后一条消息，之后的一概不记得。

使用 [`/bro`](../bro/SKILL.md) 的语气，而不是它的任务：平实的话、短句、不用行话，就像一个人在给另一个人补进度。说对用户而言什么变了，而不是你怎么做的。说"测试通过了"，而不是"CI 是绿的"。除非用户需要某个哈希、文件路径、命令、构建号或测试数量才能行动，否则略去它。用用户会知道的名字来称呼每个 PR、分支或代理，而不是你自创的标签。如果某个事实需要背景才能理解，就给出背景，或者略去这个事实。

## 收集变化

保持这一轮只读。只用你已经有的东西制作图示：不要改代码、启动应用或任务，也不要发布任何东西。收集自那条消息以来你自己的、子代理报告的，以及这个对话中其他人发的消息。检查这个对话触及的每个 PR、CI 运行或代理的当前状态。核对你要展示的每个数字与其来源事实，并在更正时说明。

行动项是只有用户才能做的决定或步骤，比如产品选择、批准、不可逆操作，或你缺少的访问权限。把仍在等用户的事项都纳入，即使是在他们最后一条消息之前提出的。你自己还能做的工作不是行动项。绝不要为了填满回复而编造一个决定。用户没有要求、工作也不需要的一步不是行动项，除非它不可逆且在等用户：给它一行，不加图示。

一个决定可以覆盖很多项，比如一组等待合并的 PR。对每一项，收集它的链接、它对用户改变了什么、你的选择背后的证据、它的风险，以及你的选择。如果决定需要而你不知道某个事实，写"未知"。没有的链接就略去。

## 写回复

把字数花在决定上，而不是故事上。把发生了什么控制在 100 字以内，不计图片，发生的事更少时更短。略去对用户没有任何改变的工作。每项给约 30 字。回复随项数增长：两项总共需要远少于 150 字，不计图片；三十项则需要多得多。绝不要为了压在字数内而删项或缩项：不要用计数代替列表，不要用链接代替条目。链接可以增加深度，但仅凭回复本身就必须足够做决定。

开头用一句短话，点明在等用户的是什么，或说明没有。行动项给出细节。如果什么也没发生、也没有在等用户的，说明并停止。

然后展示发生了什么，图片优先。内嵌工作产生的截图和视频，然后是任何解释某项变化的图示。接着用每个用户要求的事项一条短要点来总结：结果如何，以及它是完成、仍在运行、失败，还是未检查。每行都按你会说出口的方式写："搜索慢是因为缺少索引"，而不是"搜索评审：完成"或"慢搜索：缺少索引"。点名途中发现并修复的任何缺陷。每行必须单独读也成立。绝不要把仍在等用户的事标为完成，并略去行动项里已经说的内容。总结之下，最多给三条改变用户认知或行动要求的短句。然后用一行点出你还能自己完成的剩余工作。

然后列行动项。提出用户拥有的决定，比如合并、批准或挑选，并给出你的选择。你会先做的一步放进你的选择里。必须先发生的事，以及无法撤销的事，也放进去。给出决定涉及的每个 PR、issue 或代理的编号或链接，在选项之间做决定时也一样。

让形态配合决定。关于单项的决定就是一条要点：决定、你的选择、它对用户改变了什么、选择背后的证据、它的风险，项名只出现一次。当多项共享一个决定时，决定和你的选择只写一次，然后每项各一条要点，风险最高的在前：它的链接和名称、它对用户改变了什么、你的选择背后的证据、它的风险。只有在某项的选择与决定不同时才点名该项的选择。即使风险很低也要给出每项的风险，比如"低风险：只改了颜色"。只有当等待的代价超过延迟时才说明等待的代价，比如截止期限或数据丢失。

对于选项之间的决定，给出工作权衡过的每个选项，各自带给用户什么、代价是什么，以及有当前状态时的当前状态。这些代价就是决定的风险，所以不要再加单独的风险行。当上面的截图展示了这些选项时，把每个选项的收益和代价写在其截图下面。

## 图示

图示是一张图：截图、视频、Mermaid 图、来自 `/visualize` 的图表或图形，或生成的图片。Markdown 表格不是图示，即使有前后对比列。

当某件事作为图比作为句子更容易领会时，就画出来：设计或系统如何运作、带每个 PR 状态的 PR 栈或依赖链、修复的前后对比，或并排的选项。绝不要画状态列表、行动项列表，或没有连线连接的方框。绝不要把同一个事实给两次，无论在文字中还是跨图示。

让每个图示小到一眼能读：最多六个方框，每框最多八个词。标签用一个人会说出口的平实词语写，而不是"Tests: pass"这样的标签。需要一句话才能说清的事实，放在正文里，或者不放。

当变化可见时，内嵌截图和视频，而不只是给链接。如果可见的变化没有截图，在其总结行标注"暂无截图"，并在那里说明屏幕上变了什么。用你已有的事实画图和图表：Mermaid 图表示事物如何连接，`/visualize` 图表表示数字。绝不编造数字，绝不画或生成你没有截取的屏幕画面。只链接存在的产物。

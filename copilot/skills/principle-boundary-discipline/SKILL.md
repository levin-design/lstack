# Boundary Discipline

把校验、类型收窄和错误处理放在系统边界。无条件信任内部代码。业务逻辑住在纯函数里。外壳薄而机械。

**为什么：** 分散的校验嘈杂、冗余，并给人一种虚假的安全感。把逻辑挡在框架接线之外，这样无需框架也能测试它。

**模式：**
- **在边界处**（CLI 参数、配置文件、外部 API、网络协议）：校验、返回错误、防御式处理。
- **系统内部：** 有类型的数据、错误传播、不重复校验。信任类型。
- **跨边界处。** 暴露领域概念，而不是边界的私有表示。把通用机制留在内部，把专用策略放在边缘。

**应用：**

校验与错误处理：
- 在解析时校验配置（边界处），而不是在业务逻辑内部
- 在边界处把原始数据解析为领域类型
- 不要通过公共接口重新导出传输、存储、框架或 wire 类型
- 如果边界已经校验过，就不要在调用链深处做冗余的 nil 检查

代码组织：
- 业务逻辑放在无框架依赖的纯函数中
- 解析函数：从原始字节到类型化状态的纯转换
- 提示词构造：结构化状态进，字符串出
- 评分与评估：从状态到结果的纯转换

**检验：**
- "这份数据现在是否正在跨越系统边界？"如果不是，校验就是冗余的。
- "这能成为一个由外壳直接调用的纯函数吗？"如果能，就提取出来。

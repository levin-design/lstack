# 自动评审机器人分诊

当 Babysit 剧本（`../playbooks/babysit.md`）处理自动评审机器人或评审自动化评论时，使用本参考。目标不是默认忽略自动评审机器人。目标是停止把每条评论都当作必需的代码改动。

## 决策准则

行动前先对每个自动评审机器人线程分类：

- `fix`：评论指出了可信的正确性、安全、隐私、数据丢失、认证、计费、迁移、幂等性、竞态或已发布行为问题。在拥有该代码的最低 PR 中修复，然后用提交 SHA 回复并解决该线程。
- `dismiss`：评论匹配已记录的低声噪模式，且当前代码/上下文证明该关切不需要代码改动。用简短理由回复并解决该线程。
- `ask`：评论新颖、高严重度、与安全/隐私/数据相关，或含义不明。询问用户，而不是猜测。

拿不准就问。跳过一条声噪的代码质量评论代价很低；跳过真实的数据或安全缺陷则不然。

## 学到的模式格式

按以下形状添加未来的模式：

```markdown
### <short pattern name>

- Confidence: candidate | recurring | strong
- Skip when: <conditions that must be true>
- Do not skip when: <risk boundaries>
- Example signal: <phrases or code context that identify the pattern>
- Source: <PR/comment URL or short historical note>
```

一两个例子用 `candidate`。经过多次真实驳回后用 `recurring`。只有当模式狭窄、反复验证且低风险时才用 `strong`。

## 反复出现的跳过候选

### 有意的 UI 或设计系统视觉改动

- 置信度：candidate
- 跳过的条件：PR 描述、截图、设计评审或附近代码明确说明该视觉改动，而自动评审机器人评论只是复述某个共享视觉默认值变了。
- 不跳过的条件：评论指向无障碍、焦点可见性、键盘导航、颜色对比度，或 PR 并未有意改动的组件 API 契约。
- 示例信号：关于焦点轮廓、按钮尺寸、间距或共享组件视觉默认值的评论，且负责人回复 “intentional” 或 “intended”。

### 自动评审机器人看不到的上层栈或栈内用法

- 置信度：candidate
- 跳过的条件：自动评审机器人把某个导出、组件、辅助函数或文件标记为未使用，而当前托管平台的 PR 列表与差异、上层栈差异或 PR 上下文表明它被栈中更晚的 PR 使用。
- 不跳过的条件：当前 PR 不属于任何栈、该符号是公共 API，或所谓上层用法无法验证。
- 示例信号：“Exported component is never used”，人类回复类似 “used upstack”。

### 并行实现期间的临时重复

- 置信度：candidate
- 跳过的条件：PR 有意重复少量代码，以保持新路径与正在删除、替换或验证中的旧路径并行。
- 不跳过的条件：重复的代码改变安全、计费、数据访问、API 行为，或长期共享抽象会明显降低风险。
- 示例信号：“Significant duplication” 或 “duplicated validation logic”，且负责人解释旧路径将被删除或重复逻辑是有意保持局部。

### 既有框架或组件不变量已覆盖该警告

- 置信度：candidate
- 跳过的条件：该关切已由共享组件、框架契约、类型不变量，或当前差异/附近代码中可见的单一事实来源保证。
- 不跳过的条件：不变量只是假设而未强制、依赖时序，或跨越值可能分叉的异步/状态边界。
- 示例信号：关于内层 popover 缺少 max-height 的评论，而共享 popover 已强制视口边界；或可空值场景中本地检查值和传入值来自同一来源。

### 负责人声明的后续或延期清理

- 置信度：candidate
- 跳过的条件：PR 负责人明确说该问题是已知后续，当前 PR 未使该行为变差，且评论不涉及高风险领域。
- 不跳过的条件：代理在无负责人输入的情况下行动、问题属于中/高严重度的产品行为，或延期会合并一个新的回退。
- 示例信号：“I'll worry about that later” 或 “we'll delete this eventually”。

### 自行撤回或明确误报的规则评论

- 置信度：recurring
- 跳过的条件：评论正文或随后自动评审机器人的回复明确说明该发现已撤回、符合规则或为误报，且代理能在本地验证相关规则。
- 不跳过的条件：唯一证据是有人在未解释的情况下对高风险问题说 “false positive”。
- 示例信号：文件命名规则评论，其正文说该文件已符合要求。

## 默认询问

不要自动跳过这些类别，即使先前的 PR 驳回过类似内容：

- 安全、隐私、认证、计费、数据保留、训练数据和权限边界方面的发现。
- 高严重度的发现。
- 迁移、模式、幂等性、并发和跨系统行为方面的发现。
- 建议修复很小、明显降低风险且不改变产品意图的评论。

历史数据显示，人类有时会驳回安全/数据流评论。把这些视为负责人的判断，而不是团队范围的跳过规则。

## 来自近期 babysit 的候选经验

在 babysit 期间或之后，把看起来对团队有用但尚未成熟的新候选经验追加到这里。一旦多个 PR 确认了某模式，优先把反复出现的候选提升到上一节。

### 手动重新实现原生浏览器行为

- 置信度：candidate
- 跳过的条件：几乎从不。当差异用人工等价物替换原生浏览器行为（原生 sticky → JS 定位克隆、原生滚动定位 → 转发 wheel/touch 事件、paint-order 遮挡 → masks/clip-path）时，自动评审机器人针对该代码的逻辑缺陷发现一直是有道理的。
- 不跳过的条件：发现涉及此类代码中的事件转发缺口（wheel deltaMode、触摸平移、边缘滚动链、点击 slop）、mask/clip 命中测试分歧，或 observer 与 React 状态时序竞态。默认 fix。
- 示例信号：“masks do not affect hit-testing”、“overlay blocks wheel scroll”、“ignores deltaMode”、“runs in the IntersectionObserver callback before React applies state”。
- 来源：一个 sticky 遮挡 PR：六轮自动评审机器人检查，约十八条发现，全部修复而非驳回。

### 契约测试漂移的声称可低成本验证，先运行测试

- 置信度：candidate
- 跳过的条件：绝不跳过验证本身；它只花一条命令。当 PR
  附带一个钉住协议或文档措辞的契约测试（对
  SKILL.md 的正则、文档措辞快照），而自动评审机器人声称“测试已不再
  匹配文档”（或反过来）时，在分类前先在 PR 尖端运行该测试。
  红色结果从经验上确认该声称；绿色结果则是驳回回复的
  具体反证。
- 不跳过的条件：不适用——这是验证捷径，不是驳回
  模式。注意，重复轮次的倾向驳回启发式在这里会误判：
  钉住措辞的测试漂移，正是因为早先的修复轮编辑了措辞。
- 示例信号：PR 上出现 “Contract test omits the pre-fix wait”，
  而其早先的修复提交改写了被钉住的段落；在尖端运行该测试恰好
  在被指出的断言上失败。
- 来源：一个钉住措辞的 PR，八轮自动评审机器人检查；尽管之前每轮
  都修复并解决，该声称在第 7 轮仍属实。

### 过时的安全评审发现在同一 PR 中已被后续修复

- 置信度：candidate
- 跳过的条件：代理式安全评审（或类似）声称缺少鉴权/校验调用，而当前 PR 尖端明显包含该确切的守卫（带测试），通常是在评审运行之后的一个后续加固提交中添加的。
- 不跳过的条件：被引用的辅助函数对所讨论的主体是空操作、检查在其守护的副作用之后运行，或缺少所称主体的覆盖。
- 示例信号：一个 HIGH 级 “missing authorization check” 发现，而尖端在副作用之前已经调用了该确切守卫。
- 来源：一个 webhook 端点 PR，其加固提交晚于评审运行。

### 放宽刻意狭窄的错误条件会掩盖真实错误

- 置信度：candidate
- 跳过的条件：发现要求把狭窄的错误条件（特定
  `errno`、错误码或状态类别）放宽为万能捕获，而这种狭窄
  编码了真实区分。典型形态是以 `ENOENT` 为门的依赖
  回退：“binary is not installed” 与
  “the command ran and failed” 是不同情形。对任何非零退出都重试，
  会把合理的失败（未找到、认证过期、网络）对着回退
  再跑一遍，然后报告回退的错误，掩盖真实的错误。
- 不跳过的条件：该狭窄条件漏掉同一类别中的情形
  （另一个“二进制不可用”的 errno，如 `EACCES`，另一种传输层
  失败），未处理路径会丢数据或留下部分状态，或重试
  是幂等的并且原始错误仍会被暴露。
- 示例信号：“only retries when X fails with ENOENT … never tries the
  fallback even when a working Y exists”，指向其回退
  是为缺失依赖而非失败操作而存在的代码。
- 来源：一个 CLI 重命名 PR，其回退是为缺失的二进制而非失败的
  命令而存在。

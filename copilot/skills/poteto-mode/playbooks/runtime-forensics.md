### Runtime forensics

**诊断由你负责。对活进程做埋点，不要从源码臆测。** 交付物是带引用的诊断，不是修复。

1. 通过控制技能在匹配界面上捕获实时信号：对空转进程抓 CPU profile，对泄漏抓堆快照，对视觉故障抓 CDP trace。要真实产物，不要猜测。
2. 把产物归约为确凿证据：热路径上的函数、从泄漏对象到 GC 根的持有链、无输入却在触发的循环。在子代理中解析大产物（**guard-the-context-window** 原则技能），把归约后的发现留在主线程。按 Subagents 一节为每项工作选择子代理的推理级别以及快速或标准速度。
3. 相信机制之前先证明它。通过 CDP eval 向运行中的进程注入埋点，或不重载直接热修线上代码，廉价地确认假设。
4. 把发现映射回源码：文件、符号、分配或调度所在的行。
5. throughput checkpoint 保持一行：`throughput checkpoint: n/a, read-only forensics`。

**回复：** 捕获的信号、归约后的发现、你如何证明机制、源码位置、产物路径。除非被要求，否则不修复。原因明确后交回 Bug fix 或 Perf。

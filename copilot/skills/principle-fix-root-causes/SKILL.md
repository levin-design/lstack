# Fix Root Causes

调试时，修复故障，而不是故障浮现的地方。症状是错误状态变得可见的位置。根因是系统第一次做了它不该做的事，或未能处理它本应处理的状态的位置。

**为什么：** 症状式修复会隐藏证据，让故障自由地在别处浮现。每一次都会让系统更难推理，因为代码现在带着一个无人点名的缺陷的绕过方案。

**模式：**
- 先复现。
- 每一步都问"为什么"，直到答案落到代码中的一个错误决策，而不是更早决策的后果。
- 卡住时，加插桩。读真实的错误和真实的状态。不要猜。
- 问触发症状的状态是否合法。如果系统可能处于该状态，那么在该状态上出错的代码就是根因，在那里处理该状态就是修复。如果该状态本不应存在，在出错处加检查只会隐藏缺陷。找出产生该状态的东西。守卫、重试、吞掉的错误、被夹紧的值、被丢弃的状态，都是隐藏缺陷的常见方式。
- 当某件事只在重启后失败时，先怀疑持久化状态：配置文件、缓存、锁文件、序列化状态。
- 检查模式，而不只是实例。找出每一处有同样故障的地方并全部修复。
- 如果某个绕过方案需要一段段落的注释来辩护，那就是代码错了。修代码，不要修注释。
- 如果决定性的事实花了很深的挖掘才发现，提议那个廉价、常开、本可在第一眼就显示它的信号。

# Notes 验证地图

本目录是验证 Notes 用户可见行为的维护来源。驱动应用前先阅读索引，然后将匹配的功能文件用作配方。

## 基线前置条件

- 用一次性数据目录在 `http://127.0.0.1:4173` 启动 Notes。
- 设置 `NOTES_DATA_DIR=/tmp/notes-verify-$RUN_ID`，使并发运行不共享状态。
- 播种标题为 `Quarterly plan` 和 `Grocery list` 的笔记。
- 将 `control-notes` 和 `notes` CLI 放入 `PATH`。
- 运行 `control-notes doctor`，要求预期的 URL、数据目录和构建修订版本。
- 绝不驱动不是由本次验证运行启动的实例。

## 驱动约定

- 除非其前置条件另有说明，每个配方都从基线状态开始。
- 优先使用 ARIA 角色和无障碍名称，而非 CSS 选择器或 DOM 位置。
- 将每条命令视为字面量。保持引号内的名称和标志不变。
- 通过 `control-notes browser` 执行浏览器操作。
- 通过 `control-notes cli -- <command>` 执行终端操作。
- 变更后恢复种子数据。清理时不要移除证明产物。

## 证明与跳过报告

- 捕获用户操作及结果状态，而不仅仅是最终屏幕。
- UI 证明包括 ARIA 快照和一张能看到应用标识的截图。
- CLI 证明包括命令、stdout、stderr 和退出码。
- 变更证明包括对存储值的只读二次查看。
- 在每个产物中记录所用功能 ID 和入口点。
- 报告不可达路径时，附上尝试的命令和未满足的前置条件。
- 不要将通过另一条路径验证的跳过入口点报告为已验证。

## 功能条目契约

每个功能文件以 H1 标题和一段描述用户可见行为的段落开头。然后按此顺序恰好使用四个 H2 章节。

1. `Sub-features` 列出简短 ID，每个行为一行。
2. `How to get to it (user POV)` 列出每个用户入口点。
3. `Driving it with <harness>` 以 `Preconditions:` 开头，使用带标签的要点，将每个用户操作与确切命令和可观察结果配对。
4. `Gotchas` 列出可能浪费或使验证运行失效的陷阱。

地图中不要包含实现细节。只命名用户路径、稳定句柄、所需状态、命令和可观察证明。

## 功能

- [创建笔记](./create-note.md) 涵盖浏览器与 CLI 创建、取消、持久化和清理。
- [搜索笔记](./search.md) 涵盖工具栏、键盘和 CLI 搜索，以及匹配、空结果和清除状态。

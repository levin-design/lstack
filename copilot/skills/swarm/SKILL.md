# Swarm

## 开始

启动任何东西之前，先开一个待办清单，每个阶段一项。

1. Frame
2. Fan out
3. Aggregate
4. Report

## 阶段 A：Frame

1. 说明完成判据，以及 swarm 必须返回的产物或报告。
2. 选择形态。按切片分区、让 N 个工作代理按相同任务书竞速，或两者混用。对于竞速或混合形态，在启动前声明 `first pass`、`rank all` 或 `best-of`。
3. 当 `.github/skills/lstack/references/lstack-models.md` 中的 `swarm workers` 行记录了已确认的标签时，从该行选择工作代理模型。没有这一行时，工作代理继承父模型，因此省略 `model`。绝不虚构模型标签。如果 `runSubagent` 拒绝某个标签，就省略 `model` 并说明这一点。对于模型竞速，预先指明每个竞速臂的已确认模型；只有一个模型确认时跳过竞速。
4. 当工作代理需要写入时，给它各自可写的输出位置。当工作代理验证或测量提交时，每份任务书要写明确切的 SHA。测量任务书还要写明方法（样本数、一个样本是什么、顺序）。工作代理在其结果中记录这两者。

## 阶段 B：Fan out

在一个工具块中启动全部 N 个工作代理，每个工作代理一次 `runSubagent` 调用，第 3 步的模型留空以继承父模型。Copilot 子代理在本工作区同步运行。当某个工作代理必须从非默认的已推送分支开始时，在它的任务书中写明该分支，并让它自己先检出该分支再开始工作。

每份任务书都独立成立。包含目标、范围、确切的切片或竞速臂、如何验证，以及要报告什么。报告使用 `PASS`、`ISSUES` 或 `BLOCKED`，并附证据。能证明缺陷的工作代理报告 `ISSUES`，并列出它能证明的每一个问题，而不只是第一个。

如果某个工作代理掉队，就以 N-1 继续，并记录。

## 阶段 C：Aggregate

阅读终端结果。丢弃未记录任务书所指定 SHA 和方法的结果，并重新启动该工作代理一次。第二次仍未记录时，记为缺口。缺口不算通过。对于覆盖类任务，每个必需的切片都需要一个结果。对于竞速，应用预先声明的选择规则。使用 first pass、rank all 或 best-of。不要粘贴工作代理的原始输出。

## 阶段 D：Report

返回一份合并的对话内报告，包含结果表、问题一句话摘要、缺口或掉队情况，以及使用时的竞速规则。

# Control-adapter 契约

Benny 并不知道如何启动或驱动每一个应用。用户必须配置一个 control skill 或 adapter，为目标应用实现本契约。

在 `control.skill_name` 中设置其技能名称。

在 `control.feature_map_path` 中设置已完成的面向用户的 feature map 路径。把 [`feature-map.example.md`](./feature-map.example.md) 复制到 `.cursor/automations/benny/` 之外并填写，而不是编辑复制过来的示例。

如果 skill、feature map 或任何所需能力缺失、含糊或不完整，复现与修复工作必须 fail closed。

## 所需能力

### 启动

在请求的测试环境中启动请求的应用修订版本。

输入：

- 仓库和修订版本
- 构建或启动模式
- 工作区、账号、fixture 和功能状态要求
- 制品目录
- 已完成的 feature-map 路径

返回：

- 会话标识符
- adapter 如何确认正确的应用和环境
- 稳定的应用标记
- 后续调用所需的运行进程或目标详情
- 任何缺失的能力

adapter 必须能把目标应用与相似的窗口、shell 或生产实例区分开来。

### 驱动 UI

执行真实的用户操作：

- 点击
- 输入
- 按键
- 滚动
- 拖拽
- 调整大小
- 通过应用控件导航

优先使用 role、label 和稳定选择器。只有在新截取一张截图之后才使用坐标。

返回每个动作以及观察到的状态变化。

不要设置内部状态、调用隐藏的应用方法、直接写入存储，或注入 DOM 变更来制造症状。

### 驱动已映射的功能与状态

在驱动应用之前读取相关的 feature-map 小节。

adapter 必须提供以下方式：

- 通过用户可见路径导航到每个已映射的功能。
- 调用该功能列出的 adapter 动作名。
- 在适用时与 default、hover、focus-visible、active、disabled、loading、empty、error、selected、open、expanded 以及该功能特有的状态交互。
- 通过安全的 fixture 数据、权限、flag、服务响应或受支持的测试控件布置某个状态。
- 重置该功能以便进行第二次独立的复现尝试。
- 采集 feature map 指定的截图、视频和只读交叉核对。

使用 role、可访问名称、ARIA 关系、稳定的组件标记，以及按用途命名的 data 属性。绝不要使用生成的 CSS 或 StyleX 类名、动态哈希、子节点索引或脆弱的 DOM 位置。

布置前置条件不等于允许注入所报告的症状。复现本身仍必须来自真实用户交互。

### 检查状态

读取状态以确认 UI 显示了什么。

例如：

- 可访问性树
- DOM 或视图层级
- 进程状态
- 本地日志
- 网络请求状态
- 应用暴露的调试状态

检查是只读的。如果某个查询改变了状态，它属于 `驱动 UI`，且必须代表真实的用户动作。

### 截图

把当前应用状态采集到请求的路径。

返回：

- 文件路径
- 采集时间
- 应用标记或窗口标题
- 应可见内容的简短描述

截图必须展示足够的应用界面框架，以证明测试的是正确的应用。

### 录制

围绕完整的复现路径启动和停止屏幕录制。

返回：

- 文件路径
- 开始和停止时间
- 捕获的窗口或区域
- 是否省略了音频或敏感浮层

录像必须展示判别性的最终状态，而不仅是安装步骤或加载界面。

### 清理

停止由 adapter 创建的进程和会话。

删除一次性内容：

- 浏览器或应用配置文件
- 临时工作区
- adapter 创建的测试账号或 fixture
- 调试端口和隧道
- 超过保留窗口的截图

返回哪些被停止、删除、保留，或留给人工处理。

清理不得删除用户的工作。

## Adapter 行为

adapter 必须：

- 在复现开始前报告能力。
- 报告它能驱动哪些 feature-map 小节，哪些被阻塞。
- 基线构建和打过补丁的构建使用相同的环境输入。
- 把启动失败如实暴露为失败。
- 限制重试次数。
- 让密钥远离日志和制品。
- 把截图保存在仓库之外。
- 在两次复现尝试之间支持全新或重置的状态。
- 避免生产变更，除非用户明确配置了安全的测试操作。

## 环境转译

在宣布环境阻塞之前，脱离平台特有的名词重述该缺陷，并询问相同的行为是否可以在可用环境中安全测试。

示例：

- 具名浏览器可能意味着任意外部浏览器。
- 具名按键可能意味着配置的快捷键。
- 具名远程主机可能意味着延迟或断连的远程目标。

只有在测试同一底层行为时才使用转译后的尝试。把它标注为转译证据。当缺失的环境本身是缺陷的一部分时，不要称其为精确复现。

硬件提示、操作系统权限对话框、仅设备可用的 API 以及不可用的账号状态可能是真正的阻塞。

## Setup 检查

在启用 repro 自动化之前，运行一次无害的 adapter 检查：

1. 启动应用。
2. 确认稳定的应用标记。
3. 加载一个已完成的 feature-map 小节。
4. 通过其用户路径导航到该功能。
5. 通过已映射的 adapter 动作演练一个一次性状态。
6. 检查产生的状态。
7. 采集截图。
8. 录制一段短剪辑。
9. 清理。

只有当全部九个步骤成功且不涉及任何 source-channel Slack 发帖时，才启用 repro 工作。
